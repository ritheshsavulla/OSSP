Operating Systems Concepts Demonstrated in this System

1. Traditional File I/O vs Memory-Mapped I/O

Standard read() and write() require context switches between User Space and Kernel Space, copying data between Disk → Kernel Page Cache → User Buffer. In contrast, mmap() bypasses double copying by mapping file pages directly into the process virtual address space, enabling Zero-Copy direct pointer access.

2. Virtual Address Space & Page Tables

When mmap() executes, the kernel reserves a Virtual Memory Area (VMA). The address returned (e.g. 0x7f8d4...) belongs to the process user space. Memory translation is handled by the CPU Memory Management Unit (MMU) through hardware Page Tables.

3. Demand Paging & Major Page Faults

Upon mmap(), disk blocks are NOT immediately loaded into RAM. When the CPU executes the first instruction accessing the memory pointer, the MMU triggers a Page Fault exception. The Linux kernel catches this and loads the 4 KB page from disk into physical memory on demand.

4. Cache Coherency & msync()

When modifying bytes via memory pointers (memcpy), the CPU marks the Page Table entry's Dirty Bit. The changes exist in RAM. Calling msync(addr, len, MS_SYNC) instructs the kernel to immediately flush dirty pages to physical block storage.

Resize File Boundary (ftruncate)

Adjusting the file size triggers the Linux ftruncate() system call. If the file is actively mapped, it will automatically synchronize dirty pages, unmap the old region, and remap the new size.
